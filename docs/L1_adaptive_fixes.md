# L1 自适应增广 —— 调试与修复记录

本文档记录将 L1 自适应增广（`u = u_baseline + u_ac`）接入 ROS MPC tracking
（acados / crocoddyl，CTBR 推力+体角速度接口）过程中发现并修复的若干问题。
核心结论：L1 能消除由**恒定模型失配**（推力/最大推力标定错误、负载、阻力、风）
造成的稳态误差，但其与 baseline、PX4 内环、模式切换的**接线方式**必须正确，
否则会出现欠补偿、漂移、左右不对称、模式切换掉高等现象。

涉及文件：
- `scripts/l1_adaptive.py` —— L1 估计器/补偿器核心
- `run_tracking_controller.py` —— ROS 控制节点（L1 接线）
- `uam_suite_gui.py` —— GUI 显示与参数
- `scripts/example/l1_acados_*.py` —— 离线 acados 验证仿真

---

## 背景：L1 在做什么

把世界系平动写成

```
v̇ = a_nom + σ
```

- `a_nom`：名义模型下、当前 baseline 指令（推力+姿态）应产生的比力加速度；
- `σ`：集总扰动（阻力、风、负载、推力/质量误差等）的等效世界系加速度。

L1 三件套：状态预测器 → 分段常数自适应律（增量/积分形式，DC 无偏）→ 低通滤波
得到补偿 `a_ac = LPF(-σ̂)`。补偿映射到 CTBR：
- **竖直**：`ΔF = m·(a_ac·b3)` 注入总推力；
- **水平**：把 `a_ac_xy` 映射为体角速度修正（倾转机体）。

能否消除某误差，取决于两个门槛：
- **门槛 A（可观）**：误差在加速度层表现为 `σ = a_real - a_nom ≠ 0`；
- **门槛 B（可落地）**：补偿 `a_ac` 能被真正、完整地施加（执行通道无增益损失/延迟/饱和）。

## 修复 1：自适应律稳态有偏 → 改增量（积分）形式

**现象**：离线测试中 `σ̂` 相对真实扰动有约 18% 的稳态偏差。

**原因**：绝对式分段常数律 `σ̂ = -k_pc·ṽ` 在有限采样周期下存在 `e^{-a_s·dt}`
的稳态偏置，不利于精确估计慢变扰动（如质量变化）。

**修复**：改为**增量（积分）形式**

```
σ̂ ← σ̂ - k_pc · ṽ ,   k_pc = a_s·e^{-a_s·dt} / (1 - e^{-a_s·dt})
```

稳态 `ṽ→0 ⇒ σ̂→σ`，DC 无偏。位置：`scripts/l1_adaptive.py` 的 `step()`。

---

## 修复 2：欠补偿 —— 预测器输入必须含补偿后的“实际施加加速度”

**现象**：加 L1 后仍有明显残差，`σ̂` 只收敛到真实扰动的约一半。

**原因**：预测器输入只用了 baseline 名义加速度 `a_nom`，没有计入已施加的补偿
`a_ac`。这使 `σ̂` 收敛到 `σ/2`（欠补偿）。

**修复**：预测器输入用“**实际施加的**名义加速度”（含补偿）。竖直注入推力不含在
baseline 推力里，故须计入。（注意：水平通道的正确计入方式见**修复 6**，不是简单
`+ a_ac`。）

## 验证：MPC 仿真中 L1 对“恒定增益误差”的鲁棒性

为回答“CTBR/推力映射不准时 L1 是否还有效”，在 acados 悬停 MPC 仿真中注入
**执行器推力增益误差 `k`**（实际推力 = `k×指令推力`，估计器不知道 `k`）。

脚本：`scripts/example/l1_acados_thrust_gain_sweep.py`

| k（推力映射误差） | MPC only 稳态 \|e_z\| | MPC + L1 稳态 \|e_z\| |
|---|---|---|
| 0.5 (−50%) | 0.26 m | 0.048 m |
| 0.7 | 0.112 m | **0.000 m** |
| 1.2 (+20%) | 0.044 m | **0.000 m** |
| 2.0 (+100%) | 0.131 m | **0.000 m** |
| 0.4 (−60%) | 发散（落地） | 发散（落地） |

**结论**：常值增益误差 `k∈[0.5, 2.0]` 全部被 L1 吃掉、稳态归零。`k=0.4` 双双发散
是**物理推力饱和**（满油门也托不住），与 L1/CTBR 准不准无关。

## 关于 max_thrust 标定错误（30N 实际 / 50N 假定）

**问题**：MPC 假定最大推力 50N，实际 30N（`k=0.6`，经 PX4 归一化转换）。纯 MPC
无积分 → 稳态掉高。**只用速度型 L1（不开位置积分）能否消除？**

脚本：`scripts/example/l1_acados_hover_max_thrust_sim.py`

| 工况 | 稳态 \|e_z\| |
|---|---|
| 仅 MPC | 0.175 m |
| MPC + **纯速度型 L1** | **0.00000 m** |
| MPC + L1 + posI | 0.0006 m |

**结论（反直觉）**：竖直方向的 max_thrust/推力增益误差，**纯速度型 L1 即可完全
消除，无需位置积分**。原因：L1 补偿推力与真实推力**走同一条 PX4 折扣通道**（同乘
`k`），闭环自洽 ⇒ 稳态 `T_actual = T_base = mg`。`σ̂_z` 精确收敛到
`(k-1)·T_cmd/m = -6.54 m/s²`，与理论吻合。

## 速度型 L1 vs 速度+位置型（posI）能力对照

| 误差来源 | 物理表现 | 速度型 L1 | + posI |
|---|---|---|---|
| 恒定外力 / 风 / 负载重力 | 常值 σ | ✅（竖直完全；水平视通道） | ✅ 更稳健 |
| 阻力（定常速度） | 常值 σ | ✅ | ✅ |
| 慢变扰动（< L1 带宽 wc） | 慢变 σ | ✅（小滞后） | ✅ |
| 快变扰动（> 带宽） | 高频 σ | ❌ 部分 | ❌ |
| 质量误差（负载） | 常值 σ_z | ✅ | ✅ |
| max_thrust / 推力增益误差 | 常值 σ_z（同推力通道） | ✅ **完全** | ✅ |
| 水平 CTBR 内环增益不足/延迟 | 补偿**落不了地** | ❌ 留位置残差 | ✅ 消除 |
| MPC 无积分 → 常值失配 | 常值 σ | ✅（L1 当积分） | ✅ |
| 状态估计——位置常值偏置 | p_meas = p + b_p | ❌ | ❌（消不掉传感器偏差） |
| 状态估计——速度常值偏置 | v_meas = v + b_v | ⚠️ | ⚠️ |

要点：
- **竖直推力类误差**：速度型够，posI 非必需；
- **水平内环不理想**：违反门槛 B，须 posI 兜底；
- **状态估计偏置**：控制层（含 L1/posI）都消不掉，属传感器/标定问题。

## 修复 3：起步预热（warm-start priming）

**现象**：点 start_tracking 后偶发起步掉高。

**原因**：`_svc_start_tracking` 立刻开始计时且清空 warm-start，首拍是冷启动
（horizon 猜成 `x_now + u_hover`），RTI 有限迭代下首解质量差 → 推力短暂不足。

**修复**：新增 `_prime_tracking_warm_start()`，在**正式计时之前**用当前状态在轨迹
起点反复求解若干次预热（acados 用其 `warmup()`；crocoddyl 用 `_solve_mpc` 循环），
期间用 `_mpc_rebuilding` 守卫挡住控制定时器，避免并发调用非可重入求解器。预热后
再置位 `trajectory_started` 并启动计时。位置：`run_tracking_controller.py`。

> 注：这是通用稳健性改进。用户场景的“起步掉高”真因实为**修复 4**。

## 修复 4：模式切换硬重置清零了已收敛的 L1 估计

**现象（关键定位）**：纯 MPC 正常；**推力不匹配 + 开 L1，补偿到目标点后再点
start_tracking**，才出现掉落/轨迹被带偏。

**原因**：`_svc_start_tracking` 里调用了 `self._l1.reset(...)`，把 regulation 阶段
**已收敛**的 `σ̂ / a_ac / pos_integral` 全部清零。推力不匹配（k<1）下，补偿瞬间归零
→ 推力塌回不足 → 掉落 → L1 从头重新收敛（~2–3s），期间轨迹被带偏。

**修复**：新增**软重置** `L1AdaptiveAugmentation.reseed_predictor(v_world)`：仅把预测器
速度 `v̂` 对齐当前速度，**保留**已收敛的 `σ̂ / a_ac / a_l1 / pos_integral`。
start_tracking 改用软重置，且不再清零 `_l1_last_a_applied`。扰动在切换前后不变，
补偿无缝带过去 → 不再掉落。位置：`scripts/l1_adaptive.py`、`run_tracking_controller.py`。

## 修复 6（核心）：水平 σ̂ 漂移 + 左右不对称 —— 水平 a_ac 被重复计入

**现象**：Z 估计正常；XY 异常。例如 `(-1,0,1)→(1,0,1)` 到达悬停后 X 方向仍有
约 **-7.5N** 力估计；反向 `(1,0,1)→(-1,0,1)` 悬停时 X 方向有约 **-1.9N**。两件怪事：
**悬停无外力却有水平力估计**、**左右不对称**。

**原因**：预测器输入 `_l1_last_a_applied = _baseline_accel_world(thrust_baseline_N) + a_ac`，
其中 `_baseline_accel_world` 用**测量姿态** `b3_meas` 计算比力。两通道处理不一致：
- **竖直**：`a_ac_z` 经注入推力实现，而 baseline 推力**不含**注入，故显式 `+ a_ac_z`
  正确、可观；
- **水平**：`a_ac_xy` 经**倾转机体**实现，其效果**已体现在测量姿态 `b3_meas`** 里；
  再显式 `+ a_ac_xy` 就是**重复计入**。

代数后果：水平稳态退化为恒等式 `σ_true_xy = 0`，`σ̂_xy` 变成**自由积分器**、失去
可观性 → 随飞行（减速暂态）历史漂移到任意值 ⇒ 悬停残留 + 左右不对称。

**修复**：新增 `_l1_predictor_accel(thrust_baseline_N, a_ac)`，预测器输入改为用
**测量姿态 + 实际总推力**算比力，**不再显式 `+ a_ac`**：

```
a_applied = (T_actual / m) · b3_meas - g·e3
T_actual  = thrust_baseline_N + m·(a_ac·b3)
```

- 水平：`a_ac_xy` 只通过测量姿态体现一次（去重）；
- 竖直：通过 `T_actual` 计入注入推力，**与原 Z 行为数学等价**（新旧之差
  `=(a_ac·b3)·b3 - a_ac`，水平悬停时恰为 `[-a_ac_x, -a_ac_y, 0]`，Z 不变）。

修复后水平稳态 `σ̂_xy → σ_true_xy`，可观性恢复：悬停时 `Fx/Fy → 0`、左右对称。
位置：`run_tracking_controller.py`（`_l1_predictor_accel` 及两处 CTBR 发布点）。

> 注意：本修复解决的是**估计漂移**。若 PX4 姿态内环“装不满”水平倾角（增益不足/
> 延迟，违反门槛 B），即使 σ̂_xy 估对，**补偿落地仍可能不足** → 残留**水平位置
> 误差**（非力估计漂移），此时才需开 `l1_pos_fb`（位置积分兜底）。
>
> PX4 模式（非 CTBR）的预测器输入基于参考加速度、不经测量姿态，无此重复计入问题，
> 未改动。

## 实践要点小结

1. **竖直/高度静差**（max_thrust、质量、负载）：纯速度型 L1 足够；若 ROS 里没归零，
   先查 `max_thrust_total` 是否在线更新、补偿是否被二次归一化、推力是否饱和，并把
   `l1_max_accel_z` 调到足够大。
2. **水平静差**：先确认是**力估计漂移**（修复 6 解决）还是**补偿落地不足**（开
   `l1_pos_fb`）。
3. **模式切换**：用软重置保留已收敛估计（修复 4），不要硬清零。
4. **快变扰动 / 状态估计偏置**：超出 L1 带宽或属传感器问题，控制层无法消除。
